# VDS Form Builder — Django / Python execution adapter

A trusted, server-side execution adapter that mirrors the Node adapter
(`execution-adapters/node`). It is part of the VDS Universal Form Builder
monorepo and shares the **same canonical JSON standard** and the **same
cross-language conformance fixtures**.

## What is implemented and verified

| Component | File | Verified by |
| --- | --- | --- |
| `vds.expr/1` expression engine (closed typed operators, budgets, no `eval`) | `vds_form/expressions.py` | 62 shared expression fixtures (`packages/form-conformance/fixtures/expressions.json`) |
| Server effective-state + validation (port of `form-validation`) | `vds_form/validation.py` | shared `forms.json` validation cases via compiled IR |
| Submission payload builder (hidden stripping, `inputMapping`, asset guard) | `vds_form/payload.py` | shared `forms.json` payload cases via compiled IR |
| Trusted submission handler (re-validation, fail-closed RBAC, field write protection, idempotent replay, version mismatch, redacted audit) | `vds_form/submission.py` | `tests/test_submission.py` (11 tests) |
| Django view integration (lazy import, CSRF-exempt JSON POST) | `vds_form/django_view.py` | host-project wiring (requires Django at runtime) |

## Cross-language contract

The deterministic **FormIR** produced by the TypeScript compiler is the shared
contract. Compile once and register the IR with the handler:

```bash
# from the repo root
npx tsx tools/cli/src/bin.ts compile examples/forms/contact.vds.json --json > contact.ir.json
```

The Python handler re-validates against that exact IR, so client and server
agree on visibility, required-ness, and validation rules. The IR fixtures used
by the tests are generated by `scripts/gen_ir_fixtures.ts`.

## Run the tests

```bash
cd execution-adapters/django
python3 -m pytest -q
```

No Django installation is required for the core/conformance/submission tests
(Django is only needed for `django_view.py` at runtime in a host project).

## Security guarantees (identical to the Node adapter)

- Every submission is **re-validated and re-authorized on the server**; hiding a
  field on the client is never authorization.
- Operations resolve only against a registered `OperationRegistry`; a missing
  operation fails with `SUBMISSION_EXECUTOR`/`SUBMISSION_OPERATION_UNRESOLVED`.
  There is no generic endpoint and no fake `submit()`.
- RBAC is **fail-closed**: declared `submitPermissions` with no evaluator →
  `RBAC_NOT_CONFIGURED`; missing permission → `PERMISSION_DENIED`.
- Idempotent replay returns the recorded result without re-execution.
- Audit entries record value **paths only**, never submitted values.
