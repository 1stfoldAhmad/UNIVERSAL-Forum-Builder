# VDS Form Builder — Django / Python execution adapter

A trusted, server-side execution adapter that mirrors the Node adapter
(`execution-adapters/node`). It is part of the VDS Universal Form Builder
monorepo and shares the **same canonical JSON standard**, the **same
deterministic FormIR**, and the **same cross-language conformance fixtures**.

| Django view integration (server-derived auth, CSRF-exempt JSON POST) | `vds_form/django_view.py` | `tests/test_django_view.py` (real Django `RequestFactory`) |

## Security boundary (audit P0/P1)

1. **Identity is server-derived, never client-supplied.** `handle(request, auth)`
   takes the principal as a **separate, trusted second argument**. The view
   derives `auth` from `request.user` or a host `auth_resolver` that reads
   validated token claims — **never** from the body. Any body containing an
   `auth` key is rejected with `400 AUTH_IN_BODY_FORBIDDEN`.
2. **The operation is bound to the compiled FormIR.** A client `operationRef`
   that differs from `ir.submission.operationRef` is rejected
   (`OPERATION_OVERRIDE_FORBIDDEN`); an optional `allowed_operations` allowlist
   further restricts it (`OPERATION_NOT_ALLOWED`).
3. **Idempotency is safe by construction.** Checked only *after* auth/authz/
   version; keys scoped by `tenant + user + form + operation`; canonical SHA-256
   payload fingerprint (same key + different payload → `IDEMPOTENCY_KEY_CONFLICT`);
   atomic claims (lock-guarded in-memory; UNIQUE primary key in SQLite).

## Cross-language contract

The deterministic **FormIR** produced by the TypeScript compiler is the shared
contract. Compile once and register the IR with the handler:

```bash
# from the repo root
npx tsx tools/cli/src/bin.ts compile examples/forms/contact.vds.json --json > contact.ir.json
```

The Python handler re-validates against that exact IR, so client and server
agree on visibility, required-ness, and validation rules. The IR fixtures used
by the tests are generated by `scripts/gen_ir_fixtures.ts`.

## Wiring

```python
from vds_form.submission import TrustedSubmissionHandler, OperationRegistry, SimpleRbacEvaluator
from vds_form.django_view import create_submission_view

ops = OperationRegistry()
ops.register("database:contact.create", lambda payload, ctx: repo.contacts.create(payload))
handler = TrustedSubmissionHandler(
    forms={"contact": compiled_ir},
    operations=ops,
    rbac=SimpleRbacEvaluator(),
    # idempotency_store=SqliteIdempotencyStore("/path/idem.sqlite"),  # durable
    # allowed_operations=["database:contact.create"],                # optional
)

# urls.py — auth is derived from request.user (or a verified-claims resolver).
urlpatterns = [path("api/forms/submit", create_submission_view(handler))]

# Token-based hosts: supply a resolver that reads VERIFIED claims only.
def resolve(request):
    claims = request.auth  # populated by your authentication middleware
    return auth_context_from_claims(claims) if claims else None
create_submission_view(handler, auth_resolver=resolve)
```

`create_submission_view(handler, auth_resolver=None, allow_anonymous=True)`:
public forms accept anonymous submissions; permission-gated forms are still
denied anonymous by the handler's fail-closed RBAC. Set `allow_anonymous=False`
to require authentication for every form (`401 AUTH_REQUIRED`).

## Idempotency storage

| Store | Durability | Use |
| --- | --- | --- |
| `InMemoryIdempotencyStore` (default) | **Not** durable; single process | dev / tests |
| `SqliteIdempotencyStore(path)` | Durable; atomic via UNIQUE primary key (WAL) | reference |
| host Postgres/MySQL/Redis impl | Durable, distributed | **production** — implement the protocol |

Scoped keys and fingerprints are byte-identical across Node, Python, and PHP
(verified against `packages/form-conformance/fixtures/idempotency.json`).

## Run the tests

```bash
cd execution-adapters/django
python3 -m pytest -q
```

The core/conformance/submission/security tests need no Django project; the view

## Security guarantees (identical to the Node adapter)

- Every submission is **re-validated and re-authorized on the server**; hiding a
  field on the client is never authorization.
- Operations resolve only against a registered `OperationRegistry`; a missing
  operation fails with `SUBMISSION_OPERATION_UNRESOLVED`. There is no generic
  endpoint and no fake `submit()`.
- RBAC is **fail-closed**: declared `submitPermissions` with no evaluator →
  `RBAC_NOT_CONFIGURED`; missing permission → `PERMISSION_DENIED`.
- Idempotent replay returns the recorded result without re-execution, scoped per
  principal and bound to the payload fingerprint.
- Audit entries record value **paths only**, never submitted values.

**Verified.** Core engine, validation, payload, idempotency, trusted handler,

## Breaking changes (1.1.0)

- `handle(request, auth=None)` — `auth` moved out of the request into a trusted
  second argument.
- The view rejects any body-supplied `auth` (`400 AUTH_IN_BODY_FORBIDDEN`) and
  derives identity only from `request.user` / `auth_resolver`.
- The executed operation is bound to the FormIR; a mismatching client
  `operationRef` is rejected instead of honored.
- Idempotency is scoped + fingerprinted + atomic and runs after authz.
